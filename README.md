# noita-multiplayer

Собственный кооперативный мультиплеер для полного прохождения Noita и многодневных забегов.
**Сейчас здесь анализ и проектирование, не готовый мод.** Игровая реализация ещё не начата.

## Результат анализа

Сделать такую альтернативу технически правдоподобно: EW показывает, что основные механики
достижимы. Это не «добавить RPC к Lua»: потребуются сетевой процесс, собственное устойчивое
состояние забега, интеграция с внутренней памятью Noita и адаптация ванильных генераторов/перков.
Самые большие неопределённости — не передача позиции игрока, а геометрия физики, авторитет
пиксельной симуляции, сложные касты и согласованное восстановление после аварии.

### Предлагаемая основа

На ПК хоста работает сервер забега, хранящий единую истину. Noita каждого игрока через локальный
agent передаёт снимки, запросы и события; между машинами — прямое соединение по IP. Игра хоста
подключается тем же путём, что остальные. Сервер сам не симулирует Noita: он назначает владельца
каждой активной области и сущности, хранит результаты и решает гонки подборов.

Единица хранения/авторитета предложена 512×512 пикселей — как область движка. Сетевые дельты
могут быть мельче. Посещённые области сохраняются, неактивные замораживаются. «Все чанки»
означает любой достигнутый участок основного/параллельных миров, а не предварительную передачу
бесконечного мира. Клиентский сейв — восстановимый кэш, а не ещё один равноправный мир.

Это **предложение**, а не уже утверждённый стек: Rust, QUIC, SQLite и деление на процессы ещё
должны пройти технические спайки. Принятые пользователем решения перечислены отдельно ниже.

## Что выяснилось по каждому требованию

| Требование | Что нужно | Главная скрытая сложность |
|---|---|---|
| Мир: пиксели, предметы, мобы | Native доступ к клеткам; один авторитет на область/сущность; версионированные снимки, tombstones, передача владения | Одного сида недостаточно. Профильные флаги, число смертей и время меняют генерацию. Геометрия разрушаемых пропов не сводится к позиции |
| Общие орбы и другие подборы | Серверный claim, один журнал прогресса, личное применение эффекта и курсор восстановления | У орба счётчик нативный, а награда Lua зависит от истории профиля. Повторное применение не должно выдавать ещё сердце |
| Бот после смерти | Перехват game over, перенос инвентаря в враждебного бота, собственный ИИ, атомарное возвращение вещей, спектатор | Бот и его вещи должны переживать отключение умершего и владельца симуляции; копия «до смерти» не должна восстанавливать потраченные заряды |
| Справедливый лут | Классификация источников, персональные наборы/награды и их сохранённые payload, разные правила для случайных и фиксированных вещей | Нельзя N раз переиграть весь сундук или смерть босса: там золото, сердца, опасности и глобальные эффекты, не только вещи |
| Общий доход золота | Один физический доход, начисление всем, раздельные серверно подтверждённые расходы | Самородок проходит Lua, порошок начисляется нативно. Extra Money действует при подборе. Кошельковая разница смешивает доход и расходы |
| Перезаходы на протяжении дней | Журнал с durable ACK, согласованные снимки, версии форматов, эпохи владения, восстановление без локального сейва | Неприсланные кадры после вылета восстановить нельзя; аварийное окно потерь нужно отдельно согласовать и измерить |

### Граммофоны

Ваш пример зафиксирован: у одного игрока объект целый, у другого осталась часть. Для такого
случая недостаточно синхронизировать `EntityLoad`, координаты и событие взрыва. Нужен канонический
снимок изменённой **формы физических тел**, их частей и связей. Кроме того, граммофоны спавнятся
из `_pixel_scenes.xml`, а не только из обёрнутого Lua `EntityLoad`. Получение/восстановление формы —
отдельный обязательный прототип; причину конкретного случая в EW анализ не доказал.

### Персональные перки

Спавнить три разных перка каждому недостаточно. Ваниль использует глобальную колоду,
счётчики стеков, цены реролла и поиск всех загруженных сущностей с тегом `perk`. Личный выбор,
рероллы и глобальные эффекты вроде Unlimited Spells/No More Shuffle требуют явного разделения.
Таблица таких перков: [каталог](docs/LOOT_CATALOG.md), точные callbacks: [исследование §8](docs/research/vanilla_pickups.md).

### Золото без повторного умножения

Один самородок X даёт X **каждому**, а не X/N. Сумма кошельков увеличивается на N·X намеренно.
Нельзя создать N копий самородка и начислить каждую всем. Предметный лут босса/сундука можно
сделать персональным, а его денежную часть надо выделить отдельно. Общий кошелёк здесь не нужен.

## Уже согласовано

- 2–4 игрока, N фиксируется при создании забега; все на Linux/Proton.
- Истина и сохранение на хосте, без него забег не продолжается.
- Новый проект без кода EW; сторонние библиотеки разрешены при проверенной лицензии.
- Прямое соединение по IP, без обязательного Steam Networking.
- Общий доход золота, персональные траты; сердца увеличивают max HP всем.
- Перки и магазин Святой горы персональные.
- N наград, случайные могут отличаться, исходные экземпляры закреплены за игроками; секретные
  ноты/инструменты доступны каждому с сохранением своего обязательного состава.
- Дружественный огонь — настройка; бот всегда враждебен.
- После убийства бота вещи возвращаются умершему в текущем состоянии.
- Когда погибли все игроки, забег заканчивается и сейв удаляется.

Полные формулировки: [D1–D15](docs/DECISIONS.md). Рекомендации из других документов не заменяют
эти решения.

## Воспроизведение исследования

Ванильные файлы Noita не включаются в репозиторий. Чтобы получить те же локальные пути:

```sh
python3 tools/unpack_wak.py
# либо другая установка и каталог:
python3 tools/unpack_wak.py /path/to/Noita/data/data.wak /tmp/noita-data
```

Утилита пишет только в каталог назначения; по умолчанию это игнорируемый `.cache/noita-data`.
Существующие файлы там перезаписываются при повторном запуске. Установка игры и сейвы не меняются.

Исследованы местные исходники EW, официальные файлы API и распакованные ванильные скрипты;
разобраны локальные сохранения и логи. Утилита реально распаковала 14 745 файлов.
**Noita не запускалась, игровая синхронизация и производительность не проверялись.** Следующий
шаг — технические ворота на отдельном тестовом профиле, не написание сразу всех подсистем.

Проверки аналитического пакета: локальные Markdown-ссылки и ссылки D/Q разрешаются; все
распакованные файлы побайтно совпали с архивом. На временных fixtures проверены вложенная
распаковка и отклонение пути, выходящего за каталог назначения. Временные fixtures удалены.

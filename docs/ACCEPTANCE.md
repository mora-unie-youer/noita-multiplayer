# Проверки приёмки и снятие технических рисков

Это **план**, проверки ниже не выполнены. Выполненное отдельно перечислено в `README.md`.
Игровые проверки только на одноразовом профиле; реальный забег пользователя не использовать.
Каждый прототип должен приложить логи, версии сборок и фактический результат, а не «не упало».

## Технические ворота до полной разработки

| ID | Эксперимент | Доказательство / условие успеха |
|---|---|---|
| G1 | Независимый NoitaPatcher и доступ к пикселям | Найдены upstream/revision/license каждого используемого файла; не перенесено ничего EW-специфичного. Изменён участок мира и считан обратно |
| G2 | Linux↔Win32 под Proton | Две Noita с разными сохранениями, агентами и локальными портами одновременно обмениваются сообщениями с одним сервером |
| G3 | Снимок мира | Вода, песок, огонь, газ и твёрдый материал переживают захват/установку; перечислены несохранённые метаданные клеток, замерены кадр и байты |
| G4 | Сериализация игрока | Жезл с Always Cast и триггерами, фляга с несколькими материалами, перки, статусы и инвентарь восстановлены после рестарта процесса, а не только в той же игре |
| G5 | Геометрия граммофона | Частично разрушенное тело и отдельные осколки совпадают после передачи и повторного входа; совпадают маски тел, не только позиции |
| G6 | Нативный сбор порошка | Доход связан с удалённым количеством золота; два игрока на одной залежи получают общий доход ровно один раз, без захвата покупок в доход |
| G7 | Смерть без game over | Урон, полиморф и смена player entity не обходят death hook; бот действительно управляется и стреляет реальным жезлом |
| G8 | Сложные касты | Разделение визуальной реплики и авторитетного эффекта работает для триггеров, таймеров, physics projectile, материалов, телепорта и summon |
| G9 | Генерация вдали от хоста | Клиент загружает новый биом, пока хост далеко; спавны не пропадают из-за решения «спавнит только хост», не дублируются при встрече |

G1, G3, G5 и G6 могут выявить необходимость собственной native DLL. Их нельзя заменить
мок-тестом Lua API. Если G1 не даёт лицензированного пути, до подключения зависимости решается
юридическая/техническая альтернатива, а не копируется DLL из установленного EW.

## Инъекции отказов: сначала headless, затем в игре

- Убить сервер до commit, после commit до ACK и после ACK. Повтор команды должен вернуть тот же
  результат. Подтверждённая покупка сохраняет и списание, и предмет; неподтверждённая не половинчата.
- Оборвать соединение во время передачи авторитета. Старый владелец продолжает слать пакеты:
  сервер отвергает старую эпоху. Восстановление всегда даёт один экземпляр.
- Потерять, продублировать и переставить snapshots/deltas/claims. Пропущенная база дельты ведёт
  к resync; устаревшая версия не откатывает мир.
- Переполнить очередь и искусственно ограничить сеть. Управление и ACK продолжают проходить,
  память не растёт бесконечно; дальние данные догоняются полным снимком.
- Заполнить диск / оборвать запись снимка / повредить контрольную сумму. Не начинается новый
  забег автоматически, ошибку видит хост; предыдущий целый снимок остаётся читаемым.
- Подать неверные версии игры/мода/материалов, токен и сертификат; неизвестный тип сообщения,
  отрицательную/чрезмерную длину, zip/zstd bomb. Отказ без падения сервера и без записи в чужой run.
- Выполнить миграцию копии многодневного сохранения. Старый исходник и резервная копия остаются
  доступны; повтор миграции не удваивает эффекты.

## Многодневное прохождение

Сочетать совместную игру и раздельную разведку, большие расстояния и несколько сеансов.
Штатно останавливать и аварийно завершать отдельно Noita, agent и server, включая хоста.
Проверять размер БД/журнала/очередей, RAM, скорость восстановления, FPS и трафик, не только
первый удачный reconnect. Для долгих жезлов с тысячами снарядов нужен отдельный stress case.

Артефакты прогона: build hashes, настройки, seed, список модов в порядке загрузки, player IDs,
последний server_seq, ревизии областей/тел, журналы обоих клиентов и сервера. В баг-репорте
отделять субъективную картинку от расхождения хешей; user report остаётся валидным repro.

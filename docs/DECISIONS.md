# Журнал решений

Каждое решение получает постоянный номер `Dn`. Отменённое решение не удаляется: оно помечается
`ОТМЕНЕНО Dm` со ссылкой на новое. Новые решения добавляются в конец.

| ID | Дата | Решение | Почему / следствия |
|---|---|---|---|
| D1 | 2026-11-18 | Поддерживаются 2–4 игрока. N фиксируется при создании забега. | N-кратные дропы (R4) считаются от N. Как менять состав посреди забега: `Q3`. |
| D2 | 2026-11-18 | У всех игроков Linux, Noita запускается через Proton. | Внутриигровая нативная часть собирается как Win32 DLL (Noita 32-битная). Сетевой процесс может быть нативным Linux-бинарём. Windows-сборка не требуется, но и не исключается. |
| D3 | 2026-11-18 | Состоянием забега владеет хост. Без хоста забег не продолжить. | Один источник правды, нет слияния сейвов. Это исключает один класс откатов, но само по себе не решает потери при авариях, ошибки репликации и передачи авторитета. |
| D4 | 2026-11-18 | Золото: общий доход и раздельные траты. Самородок в мире один, при подборе +X получают все. | Доход каждого как у соло-игрока. Сумма кошельков растёт на N·X намеренно; запрещено N физических копий дохода, каждая из которых ещё раз начисляет X всем. |
| D5 | 2026-11-18 | Перки Святой горы персональные: у каждого игрока свой набор, выбирает он сам. | Нужен персональный (несинхронизируемый) спавн перков на каждого игрока. Реролл, скорее всего, тоже персональный (`Q13`). |
| D6 | 2026-11-18 | Сердца дают общий эффект: сердце одно, подобрал один, +max HP получают все. | Подбор сердца становится событием в журнале (как орбы). Полное лечение в Святой горе: `Q12`. |
| D7 | 2026-11-18 | Проект пишется с нуля, без кода EW. | EW можно изучать как источник знаний о движке, копировать код нельзя. Сторонние зависимости разрешены D8. |
| D8 | 2026-11-18 | Сторонние открытые библиотеки сообщества (NoitaPatcher, pollnet и т.п.) использовать можно. Под запретом остаётся код EW. | Уточняет D7. Разрешение пользователя не заменяет проверку лицензии, upstream revision, native ABI и доступности нужных API. Происхождение файлов берётся из независимого upstream, не из бандла EW. |
| D9 | 2026-11-18 | Транспорт: прямое соединение по IP (Tailscale/ZeroTier или проброс порта). Steam Networking не используется. | Сетевому процессу не нужен Steamworks. Хост слушает адрес и порт, клиент подключается. Аутентификация и шифрование нужны свои (у EW проверка TLS отключена). |
| D10 | 2026-11-18 | Урон по союзникам задаётся настройкой забега. | Настройка хранится в состоянии забега на хосте. Бот ранит игроков независимо от неё. |
| D11 | 2026-11-18 | Когда бота убивают, его вещи возвращаются воскресшему в инвентарь в текущем состоянии, с учётом трат бота. На землю ничего не выпадает. | Инвентарь бота — единственный экземпляр вещей умершего (R3.7). |
| D12 | 2026-11-18 | Забег заканчивается, когда мертвы все игроки. Сейв удаляется, как в ванилле. | Удаляется авторитетное состояние на хосте. [INFERENCE] Для защиты от ложной смерти из-за бага стоит хранить последний бэкап ещё какое-то время: уточнить при реализации (`Q20`). |
| D13 | 2026-11-18 | Магазин Святой горы персональный: у каждого игрока свой набор товаров. | Как перки (D5). Нужен персональный спавн. |
| D14 | 2026-11-18 | N-кратный дроп (боссы, сундуки, мировые уникальные вещи) даёт N разных предметов. Каждый закреплён за своим игроком, чужой поднять нельзя. | По сути это персональный лут игрока i. Реализация (видимые чужие экземпляры или невидимые) решается в архитектуре. |
| D15 | 2026-11-18 | Заранее размещённые в мире уникальные заклинания и жезлы (секреты: заклинания-ноты, жезлы-инструменты Kantele/Ocarina и подобные) должны быть у каждого игрока свои: N экземпляров или персональный несинхронизированный объект. | Полный список мест составляется по ванильным скриптам (`docs/research/vanilla_pickups.md`) и показывается пользователю. |
